# 调参策略

## 1. train_loss（训练损失）

| 曲线现象 | 诊断 | 调参建议 |
|----------|------|----------|
| 曲线下降非常缓慢 | 学习率太低，或者模型容量太小（学不动） | 增大学习率；尝试更换优化器 |
| 曲线剧烈震荡（呈锯齿状） | 学习率太高，导致模型在极小值附近反复横跳，无法稳定收敛 | 减小学习率；增大 Batch Size（更稳定的梯度估计）；使用余弦退火等平滑的学习率调度策略 |
| 曲线迅速下降然后突然不再变化（死锁） | 可能遇到了梯度消失或局部最优 | 检查激活函数（推荐 ReLU/GELU）；尝试残差连接；初始化权重 |

## 2. val_loss（验证损失）& train_loss（联合分析）

这两个指标必须结合看，用来判断模型的**泛化能力**（是否过拟合）。

| 曲线现象 | 状态/诊断 | 调参建议 |
|----------|-----------|----------|
| train_loss 下降，val_loss 也下降 | 正常训练 | 继续跑 |
| train_loss 下降，但 val_loss 开始上升 | 过拟合。模型死记硬背了训练集，但对新数据表现变差 | 增加正则化：加大 Weight Decay（权重衰减）；数据增强：增加 Mosaic、MixUp、随机旋转/裁剪等增强手段；早停：在 val_loss 最低点停止训练 |

## 3. mIoU（平均交并比）

这是语义分割最核心的指标，代表预测区域与真实区域的平均重合度。

| 曲线现象 | 诊断 | 调参建议 |
|----------|------|----------|
| mIoU 卡在某个瓶颈期（例如停在 60% 上不去） | 模型对某些难样本（如小目标、模糊边界）无能为力 | **Loss 函数**：如果只用 CrossEntropy，尝试加入 Dice Loss 或 Focal Loss 来关注难样本；**多尺度训练**：让模型在不同分辨率下学习，提升对小目标的感知；**深层监督**：在中间层也加 Loss |
| mIoU 波动很大 | 验证集可能太小，或者 Batch Size 太小导致评估不稳定 | 增大验证集数量；固定随机种子进行评估 |

## 4. Precision（精确率）vs Recall（召回率）

这两个指标通常是互斥的，需要权衡。在分割任务中，它们反映了"边缘处理"和"完整性"的问题。

### 情况 A：Precision 高，Recall 低

- **现象**：模型预测出来的区域大部分是对的（误报少），但是漏掉了很多目标区域（漏报多）。比如裂缝只检测出了一小段，或者物体只分割出了核心部分，边缘都丢了。
- **调参**：
  - 降低阈值：如果是二分类，尝试降低判定为正类的概率阈值。
  - Loss 调整：增加 Recall 相关的惩罚项。

### 情况 B：Recall 高，Precision 低

- **现象**：模型把目标区域都找出来了（不漏），但是把很多背景也误当成了目标（误报多）。比如把阴影当成了裂缝，把草地当成了路。
- **调参**：
  - 提高阈值：让模型更"挑剔"一点。
  - 增加负样本：在训练集中增加纯背景图片或容易混淆的图片。

## 5. F1 Score

F1 是 Precision 和 Recall 的调和平均数，用于寻找两者的平衡点。

| 曲线现象 | 诊断 | 策略 |
|----------|------|------|
| F1 分数不理想 | 说明模型要么太保守（漏检），要么太激进（误检），或者两者都差 | 参考上述 Precision/Recall 的调整方法 |
